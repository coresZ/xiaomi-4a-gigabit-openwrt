# 自制 VLESS 透明代理 + 上网记录页面：安装说明

这是我在这台路由器上自己做的两个后台页面，加上它们依赖的程序。**不是 OpenWrt 官方软件**，装不装随意。

另附可选的「服务 → 广告拦截」页面，复用 dnsmasq，无额外常驻 DNS 服务。它不包含在下面的一键安装步骤内，单独安装和使用见 [广告拦截说明](广告拦截说明.md)。DNS 过滤不能可靠去除 YouTube 视频广告。

| 页面 | 位置 | 做什么 |
|---|---|---|
| VLESS 代理 | 服务 → VLESS 代理 | 国内 IP 直连，其余 TCP 走所选节点；订阅解析与自动更新、手动 / 自动选节点（线路检测失败自动切换）、按设备选择、链式代理（家宽出口，分项或完整链接）、分流例外（域名 / IP 强制直连或走代理）、设置备份 |
| 上网记录 | 服务 → 上网记录 | 每台设备的流量统计与走势、访问了哪些网站和各自流量（实时数据只存内存，每日汇总存闪存 30 天）、设备备注名、禁止联网、每日流量上限、CSV 导出；可从网站记录一键把域名加入强制直连 / 走代理 |

## 先看限制，再决定装不装

- **闪存**：`xr` 程序 4.3MB。这台可写区总共约 7MB，装完只剩约 2MB。**空间很紧**，别再往里装别的大东西，升级固件前也要先看教程第 8 节。
- **内存**：路由器只有 128MB，装完可用约 15MB。设备多、连接多时可能吃紧。我给主代理设了"内存不足时最后才被杀"，链式出口测试等临时进程会优先被杀。已经去掉了节点测速功能（太占内存，也测不出真实速度）。
- **协议**：支持订阅里的 **VLESS（Reality / WS+TLS / TCP+TLS）、Shadowsocks（aes-128-gcm / aes-256-gcm / chacha20-ietf-poly1305 / xchacha20）、Trojan（TCP+TLS / WS+TLS）**。VMess、Hysteria、TUIC、Mieru，以及带 obfs / v2ray-plugin 插件或老加密方式的 SS 都不支持，这些节点会被丢掉，页面上会显示丢了多少。我实测过 Shadowsocks 和 Trojan+TCP；Trojan+WS 用手头的 2 个节点没通，没能确认是节点还是程序的问题。
- **Trojan 自签证书**：链接里带 `allowInsecure=1` 的节点会跳过证书校验（否则连不上），防中间人的能力会弱一些，密码仍然有效。只有所选节点自己要求时才会打开。
- **只代理 TCP**。我做过 UDP 版本，实测会让 YouTube 的 QUIC 反复重试而打不开，已经整个去掉了。
- **IPv6**：代理只管 IPv4，要关闭 LAN 的 IPv6，否则国外流量会绕过代理（教程 6.4）。
- 这套东西我只在 **OpenWrt 25.12.4 / 25.12.6（mipsel_24kc）** 上测过。

## 安装步骤

**最省事：用上一级目录的 `一键刷机.bat`，选 3**（交互式，会检查架构、空间、内存，逐个校验 MD5，不覆盖已有配置，不重复添加计划任务）。装之前可以加 `--dry-run` 先演练，只做检查不安装。

下面是手工步骤（脚本做的就是这些，我最初就是这样装的）：

1. 路由器上建好目录：`mkdir -p /etc/xray /usr/share/luci/menu.d /usr/share/rpcd/acl.d /www/luci-static/resources/view`
2. 按上表把文件传到对应位置（我是通过 SSH 通道 `cat > 目标` 传的，`scp` 不一定可用）。**`xr` 先传到 `/tmp` 对一下 md5 再放进去**，不要在上面直接覆盖运行中的程序。
3. 填订阅地址并启用：
   ```
   uci set xray.main.sub_url='你的订阅地址'
   uci set xray.main.enabled='1'
   uci commit xray
   ```
   订阅需要是 v2rayN 通用格式（脚本用 `v2rayN/6.0` 的 User-Agent 去拉）。
4. 开机自启和定时任务：
   ```
   /etc/init.d/xray enable
   echo '* * * * * /usr/bin/xray-sub watchdog >/dev/null 2>&1' >> /etc/crontabs/root
   echo '7 * * * * /usr/bin/xray-sub auto-update >/dev/null 2>&1' >> /etc/crontabs/root
   echo '*/5 * * * * /usr/bin/xray-sub domains-refresh >/dev/null 2>&1' >> /etc/crontabs/root
   echo '2 */4 * * * /usr/bin/netmon daily-save >/dev/null 2>&1' >> /etc/crontabs/root
   echo '58 23 * * * /usr/bin/netmon daily-save >/dev/null 2>&1' >> /etc/crontabs/root
   /etc/init.d/netmon-block enable
   /etc/init.d/cron enable; /etc/init.d/cron restart
   ```
   第一条是看门狗（代理进程挂了就撤掉转发规则，国内网站不受影响，也顺带每 3 分钟做一次线路检测），第二条每小时看一次是否到了订阅更新时间（间隔在页面里设，只有节点真的变了才重启代理），第三条把分流例外里的域名解析成地址，后两条把每天的流量汇总存进闪存。
5. 让页面生效，并启动：
   ```
   /etc/init.d/rpcd restart
   rm -f /tmp/luci-indexcache* /tmp/luci-modulecache/*
   /etc/init.d/xray start
   ```
6. 上网记录页面：打开页面点"开始记录"，或在 SSH 里执行 `netmon on`（它会打开 dnsmasq 的查询日志并加一条每分钟的定时任务）。
7. 用 `xray-sub status` 看状态。代理范围默认是 `all`（全部设备）；想只给某几台，在页面的"哪些设备走代理"里勾选。

## 更新国内 IP 表（建议每隔几个月做一次）

国内 IP 段会变，`xray.nft` 里的表是 2026-10-23 生成的。更新方法（在电脑上，需要 Python 3 和网络）：

```
cd 规则与配置
python gen_cn_nft.py
```

它会下载 APNIC 最新数据，只替换文件里国内 IPv4/IPv6 两张表，其他内容不动。我验证过：用当时那份数据重新生成，结果和随附的 `xray.nft` 逐字节一致；数据明显不对时它会拒绝写入。
然后把新的 `xray.nft` 传到路由器 `/etc/xray/xray.nft`，执行 `xray-sub rules on` 生效（不用重启代理）。表过期的后果是个别新分配的国内 IP 会被当成国外走代理，不会断网。

## 想要保留这套东西，升级固件时

**不要把 `/usr/bin/xr`（4.3MB）加进 `/etc/sysupgrade.conf`**，它会在升级后撑爆可写区（教程第 8 节有我踩过的坑）。其余小文件（脚本、页面、`/etc/xray`、定时任务、备注名和每日汇总等，合计约 0.3MB）可以保留，一键脚本会把它们登记进去。升级后只需要重新装回 `xr`（选一键脚本的 3，或手动复制）。

## 重新编译（只有想改程序时才需要）

- 基于 Xray-core **v26.10.21**，先打 `源码/xray-core-v26.10.21-精简补丁.patch`（去掉 QUIC 嗅探和 Hysteria 入站，省约 0.5MB；并给 TLS 加一个默认关闭的"跳过证书校验"开关，给自签证书的 Trojan 节点用），再把 `main.go` 放到源码树的 `mini5/` 下编译：
  ```
  GOOS=linux GOARCH=mipsle GOMIPS=softfloat CGO_ENABLED=0 go build -trimpath -ldflags "-s -w -buildid=" -o xr ./mini5
  ```
  需要 Go 1.27。最后用 UPX（`--lzma --best`）压缩，压完约 4.3MB。
- `路由器程序/xr` 的 MD5 是 `3407b2b47a42a96cdc38d07126785d4f`（4.32MB），和我路由器上正在运行的那份一致。
